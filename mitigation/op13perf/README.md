# op13perf — OnePlus 13 性能模式（可切换 / 重启自动还原）

一个 Magisk 模块。用 Magisk app 模块列表里的 **Action 按钮**循环切换
**关 → 日常档 → 极限档 → 关**。

## 它解决什么

这台机器上有两个独立的限制器，2026-08-19 实测：

| 限制器 | 表现 | 唯一能解的手段 |
|---|---|---|
| URCC 集群倒挂 | 超大核被压到 1689600，**低于**中核的 2400000 | 写 `/sys/kernel/msm_performance/parameters/cpu_max_freq`，且需 4 Hz 复写 |
| `oplus_bsp_task_overload` | 把繁忙线程钳到 `floor(614 × 超大核当前频率 / 4320000)`，钳完就被赶到中核 | 对前台进程 `uclampset -a -M 1024` |
| `cpufreq_bouncing` | 负载 50 ms 后把超大核压到 2438400，在 `min()` 下会盖过上面的请求 | 开启档位时置 0；系统每次亮屏都会重新打开，所以要复查而不是设一次 |

`scaling_max_freq` 在 `min()` 下打不过 URCC 的 `freq_qos` 请求，**所以写它没用**——这是本模块不走那条路的原因。

GB7 实测阶梯（同一天、同一操作点、接 40 W 主动散热）：

```
原厂（倒挂 + 钳位）        725 / 5942   多核÷单核 8.20
只解倒挂                  1210 / 7626   多核÷单核 6.30
两个都解                  2071 / 8166   多核÷单核 3.94
健康参考机                2681 / 8846   多核÷单核 3.30
```

**多核÷单核的比值可以当自检**：8.2 = 两个限制器都在，6.3 = 只剩钳位，3.9 = 都解决了。

## 两个档位

| | 超大核 | 中核 | 温度红线 | 自动关闭 |
|---|---|---|---|---|
| 日常档 | 2841600 | 2745600 | 90 °C | 不自动关（常开） |
| 极限档 | 3283200 | 2918400 | 95 °C | 不自动关（常开） |

**开机自动进入的档位由 `BOOT_LEVEL` 决定**（0=关 1=日常 2=极限，默认 1）。
想开机就进极限档，把 conf 里的 `BOOT_LEVEL` 改成 2。

改 `/data/adb/op13perf/conf` 可调。**填进去的值必须是 `scaling_available_frequencies`
里的真实台阶**，否则内核会静默向下吸附（2918400 在 policy6 上不存在，会变成 2841600）。

## 安全设计

- **过热是「退让」不是「关闭」**。超过红线立刻撤掉全部杠杆并把 CFB 交还系统，等平滑温度降到 `红线 - THERMAL_HYST` 以下、且已退让满 `THERMAL_DWELL` 秒，自动恢复。常开配置下硬关闭是错的——关了就再也回不来。
- **温度决策跑在指数移动平均上**。`cpu-1-1-1` 是单核结温传感器，实测一秒内在 80↔93 °C 之间来回甩；直接用瞬时值会让 6 °C 的回滞带比噪声还窄，实测 13 秒内震荡了 4 次。
- **息屏时不做温控**。息屏时本来就不施加任何杠杆，此时的发热是系统自己的，替它退让没有意义。
- **超时自动关闭默认关闭**（`*_TIMEOUT=0`），需要的话填秒数。
- **息屏暂停**两个杠杆（`PAUSE_ON_SCREEN_OFF=1`）。
- 前台进程来自内核自己的 `top-app` cpuset，**不按进程名匹配**——`comm` 截断在 15 字符，本项目已经四次栽在按名字认进程上。
- 每次写完都**读回校验**（`held=yes/no` 记在 `/data/adb/op13perf/status`）。

## 关闭时会发生什么

关闭**不是**自动回滚。写 `cpu_max_freq` 是改写 URCC 自己持有的那份请求，空载时这个写入会一直保持（实测 40 秒无漂移）。所以关闭时模块会**显式写回额定值**（4320000/3532800），意思是「本模块不施加任何限制」；URCC 会在它下一次 ramp 时重新应用自己的策略。uclamp 钳位不需要处理，停止提升后 guard 立刻自己钳回去。

CFB 会在关闭时被写回 1，交还给系统。

**旧的 `/data/adb/service.d/oneplus13_cfb_tune.sh` 已于 2026-08-19 退役**，因为它写的
`scaling_max_freq` 打不过 URCC，却让「关闭」状态不干净。但要注意：它同时还在**关着 CFB**，
这一半是有用的，已经搬进本模块。备份在 `/data/adb/op13perf/backup/`。

重启验证后的真实原厂上限是 **超大核 2649600 / 中核 1996800**（次序正常，刚开机时没有倒挂）。

## 文件

```
/data/adb/modules/op13perf/     module.prop  service.sh  action.sh  perfd.sh  uninstall.sh
/data/adb/op13perf/             state  conf  status  log  since  pid
```

`cat /data/adb/op13perf/status` 看实时状态，`cat /data/adb/op13perf/log` 看切换和自动关闭记录。

## 卸载

在 Magisk app 里移除模块即可。`uninstall.sh` 会停掉守护进程并删掉状态目录；没有任何持久化的内核改动需要还原。
